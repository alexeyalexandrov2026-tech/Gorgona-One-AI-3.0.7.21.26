# Miami Elio для iPhone

Приложение-оболочка вокруг сайта gorgona-one.com. Четыре вкладки:

| Вкладка | Что это | Откуда данные |
|---|---|---|
| Главная | сайт в веб-вью | `/` |
| Консьерж | нативный чат | `POST /api/chat` |
| Поиск | нативный поиск и быстрые разделы | `GET /api/search` |
| Профиль | сайт в веб-вью | `/profile` |

Каталог, бронирование, события, кабинеты и все 16 языков остаются на сайте — в приложении их не нужно дублировать. Изменения сайта появляются в приложении сразу, без новой версии в App Store.

## Что где лежит

- `MiamiElioKit/` — логика без интерфейса, покрыта тестами: куда ведёт каждая ссылка (`RoutePolicy`), чтение ответов чата и поиска, соответствие языков сайта и телефона.
- `MiamiElio/` — экраны на SwiftUI и веб-вью.
- `MiamiElio/Resources/Fonts/` — фирменные шрифты сайта и их лицензии.
- `MiamiElio/Resources/Assets.xcassets/World*.imageset` — фотографии разделов для экрана «Поиск», взятые из картинок сайта скриптом `scripts/import-world-photos.py`.
- `MiamiElioUITests/` — проход по вкладкам со скриншотами.
- `strings.json` + `scripts/build-strings.mjs` — тексты интерфейса. Переводы берутся из переводов сайта; файлы `Resources/*.lproj` генерируются, руками их не правят.
- `project.yml` — описание проекта для XcodeGen. Файл `.xcodeproj` генерируется и в git не хранится.

## Как собрать на Mac

```sh
brew install xcodegen
cd ios
xcodegen generate
open MiamiElio.xcodeproj
```

В Xcode выбрать симулятор iPhone и нажать Run. Для запуска на телефоне — указать свою команду в Signing & Capabilities (или `DEVELOPMENT_TEAM` в `project.yml`).

## Проверки

| Что | Как | Где запускается |
|---|---|---|
| Логика | `cd ios/MiamiElioKit && swift test` | Mac, CI |
| Сборка и UI-тесты | workflow **iOS** (`.github/workflows/ios.yml`) | CI на macOS при любом изменении в `ios/` |
| Сборка Release для TestFlight без подписи и то, что проверяет App Store Connect | job `release-archive` того же workflow, `scripts/check-release-archive.sh` | CI на macOS, рядом с UI-тестами |
| Тексты совпадают с сайтом | `node ios/scripts/build-strings.mjs --check` | CI |
| Сезон совпадает с главной сайта | `node ios/scripts/build-season.mjs --check`, `node --test tests/content/app-season.test.mjs` | CI iOS и CI сайта |
| Сайт и приложение не разошлись | `node --test tests/content/app-shell.test.mjs` | основной CI сайта |
| Скрипт, который приложение внедряет в страницы | `node ios/scripts/verify-web-bridge.cjs` при запущенном локально сайте | вручную |

Скриншоты каждого прогона UI-тестов лежат в артефакте `ios-screenshots` на странице прогона в GitHub Actions.

Если UI-тест упал, шаг «Report failed tests» (`scripts/report-test-failures.mjs`) пишет в пометки прогона (Annotations) только имя теста, файл, строку и текст проверки, очищенный от всего, что взято с экрана или относится к человеку (подписи и сравниваемые значения, почта, телефоны, ссылки, ключи, буквы не из латиницы). Скриншотов и описания экрана в пометках и в журнале нет; это проверяет `tests/content/ios-failure-report.test.mjs`. Пометки видны без входа на GitHub — на странице прогона и через открытый API (`/check-runs/<id>/annotations`); журналы шагов и артефакты открываются только после входа.

## Как приложение договаривается с сайтом

- Приложение до загрузки страницы ставит на `<html>` атрибут `data-app="ios"`. Сайт по правилу в `app/globals.css` скрывает элементы с `data-app-hidden`: подсказку «Добавить на экран Домой», плавающую кнопку консьержа и ссылки на букмекерский раздел. В обычном браузере атрибута нет, и сайт выглядит как раньше.
- Язык: при первом запуске приложение записывает язык телефона в cookie `gorgona-locale`. Дальше язык меняется переключателем сайта, чат отвечает на том же языке.
- Ссылки: страницы Miami Elio открываются внутри приложения, чужие сайты — во встроенном Safari, телефон/почта/WhatsApp — в системных приложениях.

## Внешний вид

Нативные экраны оформлены так же, как сайт (`app/design-system.css`, тёмная тема):

- **Шрифты.** Заголовки и текст набраны одним шрифтом — Jost, как на главной странице сайта: заголовки крупные, среднего начертания, с плотной расстановкой букв. Bodoni Moda и DM Mono остались только в логотипе «MIAMI Elio». Файлы взяты из Google Fonts и распространяются по лицензии SIL Open Font License — тексты лицензий лежат рядом с файлами и попадают в приложение. В файлах изменено одно: межстрочный интервал, записанный в самом шрифте (Jost: было 1,445 высоты кегля, стало 1,25; Bodoni Moda: 1,525 → 1,28), чтобы многострочные заголовки стояли плотно, как на сайте. Формы букв не тронуты; после замены файлов свежими нужно снова запустить `python3 ios/scripts/tighten-font-metrics.py`.
- **Языки.** В Jost есть латиница и русский (украинских букв в нём нет). Чтобы строка не набиралась наполовину одним шрифтом, наполовину другим, он включается только для языков, которые покрывает целиком: en, es, pt, de, tr, it, fr, pl, ru. В остальных языках используется системный шрифт Apple. Логика — в `MiamiElio/Support/Typography.swift`.
- **Цвета** — палитра сайта (`Support/Theme.swift`). Золото оставлено только для шара консьержа, как на сайте.
- **Заставка** (`App/SplashView.swift`) — золотой шар и логотип на цвете экрана запуска. Держится около секунды и не дольше трёх: уходит, как только первая страница почти нарисована, чтобы вместо пустого экрана загрузки гость видел бренд.
- **Шар консьержа в панели вкладок** — вместо системного значка. Это картинка (яркая для выбранной вкладки и приглушённая для остальных); её рисует `python3 ios/scripts/render-tab-orb.py` теми же цветами, что и шар на экране консьержа.
- **Появление содержимого** (`Support/Motion.swift`) — заголовки, плитки, подсказки и реплики мягко проявляются снизу вверх по очереди. При включённой в iOS настройке «Уменьшение движения» остаётся только проявление, без сдвига.
- **Фотографии разделов** на экране «Поиск» — те же снимки, что на сайте. После замены снимка на сайте: `python3 ios/scripts/import-world-photos.py`.

## Консьерж: живой шар, голос, сезон

- **Шар показывает, что делает консьерж** (`ConciergeMark` в `Support/Brand.swift`): в покое светится, пока гость говорит — растёт и пульсирует в такт голосу, пока ответ в пути — по нему бежит блик (вместо трёх точек), пришёл ответ — короткая вспышка. С «Уменьшением движения» шар не двигается и не меняет размер, меняется только яркость.
- **Голосовой ввод** (`Concierge/Dictation.swift`): кнопка микрофона рядом с полем. Слова появляются в поле по мере речи, отправляет гость сам. Язык — тот, что выбран на сайте (таблица `SiteLocale.speechLocales` = `SPEECH_LOCALES` в `lib/ai/locale.js`). Где iPhone умеет, речь распознаётся на самом телефоне. Микрофон выключается сам через минуту, при уходе с вкладки и при отправке. **Ответы вслух не читаются** — консьерж только текстовый, как на сайте; тест `tests/content/app-season.test.mjs` следит, чтобы синтез речи не появился.
- **Сезон** (`Season/`): под готовыми запросами — недели, которые раскупают первыми, из того же списка, что на главной сайта (`lib/seasonData.js` → `MiamiElio/Resources/season.json` скриптом `node ios/scripts/build-season.mjs`; после правки дат на сайте его нужно запустить). Нажатие на неделю — запрос консьержу «спланировать», колокольчик — напоминание за три недели в 10:00 по Майами (если три недели уже прошли — на следующее утро, но не в день начала). Напоминания ставит сам телефон, без сервера и без аккаунта Apple Developer; разрешение на уведомления спрашивается только при первом нажатии на колокольчик. Нажатие на напоминание открывает консьержа с готовым запросом в поле — отправляет гость.

## Букмекерский раздел

Раздела букмекеров на сайте больше нет: страницы удалены, старые адреса (`/sportsbook`, `/sports-betting-promos`, `/*-promos`) перенаправляют на главную. Приложение на всякий случай по-прежнему отказывается открывать эти адреса у себя (правило App Store 5.3: приложениям, продвигающим ставки на деньги, нужна лицензия) — список `defaultRestrictedPaths` в `MiamiElioKit/Sources/MiamiElioKit/RoutePolicy.swift`, тот же список на сайте — `lib/appRestrictedPaths.js`. Консьерж в приложении получает указание не обсуждать ставки (`lib/ai/appPersona.mjs`).

## Публикация в TestFlight и App Store

Нужен платный аккаунт Apple Developer (99 $ в год). Без него приложение можно только собрать и запустить в симуляторе. Пошагово для владельца и список проверок на iPhone — `docs/TESTFLIGHT.md`; коротко:

1. Записать **Team ID**, зарегистрировать идентификатор `com.miamielio.app`, создать приложение в App Store Connect.
2. App Store Connect → Users and Access → Integrations → App Store Connect API: ключ с ролью **Admin**; файл `.p8`, **Key ID**, **Issuer ID**.
3. GitHub: Settings → Secrets and variables → Actions — секреты `APPLE_TEAM_ID`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`.
4. Метка `ios-testflight-<версия>` на нужном коммите (`git tag ios-testflight-1.0.0 <коммит> && git push origin ios-testflight-1.0.0`) запускает `.github/workflows/ios-release.yml` из любой ветки; такие сборки — только для внутренних тестировщиков. Кнопка Actions → **iOS release (TestFlight)** → Run workflow появится, когда workflow окажется в `main`.

> Выгрузка ещё ни разу не запускалась: Apple-аккаунта нет. Половина без подписи — сборка Release и проверка того, что читает App Store Connect (`scripts/check-release-archive.sh`), — идёт в job `release-archive` workflow iOS на каждом изменении `ios/`. При первом настоящем запуске возможны правки.

## Что нужно сделать до отправки на ревью App Store

Полный и более свежий список, результаты проверок и черновик текстов для страницы в магазине — `docs/APP_STORE_READINESS.md`.

- **Удаление аккаунта.** Apple требует (п. 5.1.1(v)), чтобы аккаунт, созданный в приложении, можно было удалить из приложения. На сайте такой функции сейчас нет. Без неё ревью откажет.
- **Анкета о приватности** в App Store Connect. Приложение передаёт: имя, e-mail и телефон (заявки на бронирование и регистрация) и текст обращений к консьержу. Для слежки и рекламы данные не используются.
- **Скриншоты и описание** для страницы приложения.
- **Проверка на настоящем iPhone.** Приложение проверено только в симуляторе на CI.
