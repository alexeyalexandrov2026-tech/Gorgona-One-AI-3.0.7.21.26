# Concierge WebKit acceptance — November 2, 2026

Status: the bounded focus defect is fixed and verified on protected staging. This is not full public-launch or physical iPhone acceptance.

## Acceptance and architecture

Both concierge dialogs must retain keyboard focus while open and restore it to the clicked opener after Escape. Saved conversation/cards must survive reload and recommendation navigation across all 16 languages. Voice initialization failure must retain text recovery. These checks require no model or booking calls.

The existing `useDialogFocus` captures `document.activeElement` when opening. WebKit clicking the opener did not focus that button, so the snapshot was unsuitable. This browser distinction is documented in [WebKit's issue history](https://bugs.webkit.org/show_bug.cgi?id=22261). Hosted and local reproductions independently establish the application defect.

The fix calls the platform focus API on `event.currentTarget`, with `preventScroll:true`, before the existing toggle in `DiscoveryDock.jsx` and `AiSphere.jsx`. Existing providers, dialog hook, close behavior, routes and design are reused. No application abstraction or dependency was added.

The QA-only `browser-engine.mjs` centralizes engine selection for three existing harnesses. Chromium remains the default; `CONCIERGE_BROWSER_ENGINE=webkit` explicitly selects WebKit. A custom Chromium executable is rejected for WebKit. JSON reports record actual engine/version. The new `focus-browser.mjs` mounts actual providers, triggers and dialogs with isolated framework routing, testing both dialogs with twelve Tab presses followed by Escape.

Installed Playwright was 1.64.1. Its official CLI downloaded WebKit and its FFmpeg helper into the browser cache; package/lock files did not change. Setup follows [Playwright browser installation](https://playwright.dev/docs/browsers#install-browsers). Tested WebKit was 27.2 on Windows, with desktop/mobile viewports. [Playwright explains](https://playwright.dev/docs/browsers#webkit) that its patched WebKit is distinct from branded Safari and platform features vary. These results do not certify actual Safari/iOS or microphone hardware.
