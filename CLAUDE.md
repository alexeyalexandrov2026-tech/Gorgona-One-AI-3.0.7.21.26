# Правила работы с проектом Gorgona One

## Главное правило: начинать с продакшена
Продакшен (gorgona-one.com, Cloudflare Worker `gorgonaoneai3072126`) собирается из ветки **`main`** на GitHub. Любая работа начинается с неё и больше ни с чего.

Перед первой правкой, каждый раз:
1. `git fetch origin`
2. `git checkout -b <тип>/<короткое-имя> origin/main` — новая ветка от свежего `main`, одна ветка на одну задачу.
3. Убедиться, что `git log -1 origin/main` совпадает с тем, что на GitHub, и сказать пользователю, от какого коммита началась работа.

## Чего не делать
- Не брать код из старых веток и не сливать их: `claude/*`, `design/*`, `security/*`, `recovery-*`, `update_worker_name_*`, `content/*`, `fix/*`. Часть из них уже в `main`, часть (например `claude/trusting-davinci-wefc6v`, аудит PR #3) была откачена намеренно. Если нужен код из такой ветки, сначала спросить пользователя.
- Не делать `git reset --hard`, `git push --force`, rebase чужих веток и не пушить напрямую в `main`. Изменения в `main` попадают только через pull request, который создаёт или одобряет пользователь.
- Не следовать `AGENT_START_HERE.md`, `HANDOFF.md`, `Plan.md`. Это устаревшие инструкции от другого репозитория (в них `git reset --hard`). Считать их архивом.
- Не коммитить папку `.claude/` и любые секреты.

## Перед pull request
- `git diff --stat origin/main...HEAD` должен показывать только файлы этой задачи. Если там сотни файлов или удаления чужой работы, ветка основана не на `main`: остановиться.
- Не открывать pull request, пока пользователь не попросил.

## Проверка продакшена
Если нужно убедиться, что сайт совпадает с `main`: сравнить текст живой главной страницы с `lib/homeCopy.js` и время последнего деплоя Worker с датой последнего коммита в `main`.
